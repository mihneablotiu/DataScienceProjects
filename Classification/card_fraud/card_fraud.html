def IQR_method (df,n,features):
    """
    Takes a dataframe and returns an index list corresponding to the observations
    containing more than n outliers according to the Tukey IQR method.
    """
    outlier_list = []

    for column in features:
        # 1st quartile (25%)
        Q1 = np.percentile(df[column], 25)
        # 3rd quartile (75%)
        Q3 = np.percentile(df[column],75)
        # Interquartile range (IQR)
        IQR = Q3 - Q1
        # outlier step
        outlier_step = 1.5 * IQR
        # Determining a list of indices of outliers
        outlier_list_column = df[(df[column] < Q1 - outlier_step) | (df[column] > Q3 + outlier_step )].index
        # appending the list of outliers
        outlier_list.extend(outlier_list_column)

    # selecting observations containing more than x outliers
    outlier_list = Counter(outlier_list)
    multiple_outliers = list( k for k, v in outlier_list.items() if v > n )

    # Calculate the number of records below and above lower and above bound value respectively
    out1 = df[df[column] < Q1 - outlier_step]
    out2 = df[df[column] > Q3 + outlier_step]

    print('Total number of deleted outliers is:', out1.shape[0]+out2.shape[0])

    return multiple_outliers

# Creating function for scaling
def Standard_Scaler (df, col_names):
    features = df[col_names]
    scaler = StandardScaler().fit(features.values)
    features = scaler.transform(features.values)
    df[col_names] = features

    return df

Documentation¶

Summary

In this project we are classifying card transactions as being fraudulent or not.

For this we are using an imbalanced dataset, as most card transactions are not fraudulent.

To combat this issue, we are trying different approaches to balance the dataset to avoid bias. All of them will be used in a Random Forest model, as it is the most accurate on average.

Implementation

First thing was to check the imbalance of the dataset. We have a percentage of 99.7% genuine transactions which leaves only a small amount of fraudulent transactions to work with.

Next step is to pre-process the data. This usually means dropping duplicates, entries with no value and outliers. In our case, we have to keep the outliers as removing them would only leave 64 fraudulent transactions.

After splitting the dataset into train and test subsets, we start implementing the different strategies to fix the imbalance. We'll be using GridSearchCV for hyperparameter tuning together with Random Forest.

First approach was the Random Resampling, which can be Random Oversampling or Random Undersampling, although in our case the undersampling method is not applicable as it would only leave 76 genuine transactions and 76 fraudulent ones.

Next approach was the SMOTE, followed by Tomek Links. SMOTE is an oversampling technique, while Tomek Links is an undersampling one. Those two can be combined into a single technique called SMOTETomek.

Lastly, another approach is class weights, meaning the minority class can have a higher weight to combat the imbalance.

Results

The recall, precision, F1 scores and accuracies for the used techniques are the following:

The SMOTE Oversampling achieved best recall score, but at the cost of the lowest precision of 0.5 and lowest F1 score of 0.67.

The reference model without under/oversampling achieved 0.81 recall.

The most advanced technique, SMOTETomek, was the worst at recall.
